
# ❦ Contributing to HEX

HEX is an experimental framework for formalizing, modeling, and executing transformations.

Contributions should preserve conceptual clarity, traceability and the experimental nature of the system.

## ❦ Contribution Principles

➜ Preserve original conceptual terminology.

➜ Do not normalize experimental names, symbols or notation without discussion.

➜ Keep changes small, documented and traceable.

➜ Distinguish theoretical proposals from tested implementations.

➜ Include reproducible evidence when proposing functional changes.

## ❦ Scope

This repository contains material explicitly selected for public development.

Private research archives, client materials, credentials and third-party content without redistribution permission must not be submitted.

## ❦ Issues

Describe the problem, its context and the expected behavior.

For conceptual proposals, explain their relationship to the existing HEX architecture.

## ❦ Pull Requests

Every pull request should include:

- A clear description of the change.
- Its conceptual or technical purpose.
- Relevant tests or validation.
- Updated documentation when necessary.

## ❦ Provenance

Contributors must have the rights or permissions necessary to submit their contributions.

Third-party material must retain appropriate attribution and licensing information.

## ❦ Development Status

HEX is experimental.

A conceptual proposal, prototype or notebook must not be presented as a validated runtime without reproducible testing.
